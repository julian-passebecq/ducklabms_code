## Implemented integration

NotebookDesktop consumes RootNotebook, Asset[], existing exercise metadata,
renderBlock, the existing NotebookCanvas and existing save/run/submit callbacks.
No source/runtime/catalog is copied into another product.

The Notebook mode renders semanticBlocks in the order of the canonical notebook
view. Canvas passes through the existing grid renderer and its layout changes.
Arena selects the actual exercise answer and linked output cells and renders
existing problem/help/evidence callbacks. Moving panels never changes semantic
order. Run and Submit remain different backend operations.

`preferredView?: string` is optional RootNotebook metadata, validated by
normalizePreferredView during restore. Absence preserves the old object shape.
UI mode, legacy tabs and presentation controls update it. Load/reopen uses it
only after restore validation. Panel geometry is separate, validated browser-local
state, keyed by workspace ID and notebook ID. It is not canonical notebook code.

The editor replacement preserves the original Monaco adapter with a guarded
plain-editor fallback. The keyboard helpers are pure and tested. Catalog preview
SQL quotes schema/table segments and inserts a cell without execution.

## Preview is explicit, not a backend fallback

main.tsx opens UiPreview only for `?preview=1`. The fixture host reuses the new
NotebookDesktop. Run and Submit stay disabled; example tables are labelled.
It uses RootNotebook's shape and source keys but its exercise IDs are not installed
backend packs. The standalone compiled harness uses offline React 16 bundles;
the real application keeps its existing dependencies. Production must not use
the fixture canvas adapter in place of the original NotebookCanvas.
