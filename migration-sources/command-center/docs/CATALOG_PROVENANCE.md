# Catalog provenance

The initial project catalog was reconstructed from the user's archived project control files rather than invented from the UI mockup.

Primary archive inputs:

- `WEBSITE_PROJECT_MEGA_ARCHIVE_2026-09-12.zip`
  - `projects_master.csv`
  - `ALL_GITHUB_REPOS.md`
  - `NETLIFY_SITES.md`
  - project dossiers and roadmap notes
- `toolsdev_mega_archive_2026-09-12.zip`
  - project status matrix
  - individual project dossiers
  - GitHub branch inventory
  - live-link inventory
- `csharp-toolspbi_MEGA_ARCHIVE_2026-09-12.zip`
  - employer showcase matrix
  - Power BI / Fabric / C# project status material
- `Contoso_Planning_Studio_V1_Source.zip`
  - local source package and release evidence

## Catalog rules

- Public deployment available -> may be `Live`.
- Working local/extension/desktop tool without a public deployment -> generally `Prototype` unless archive clearly records active implementation.
- Active implementation/handoff/recovery -> `In progress`.
- Defined roadmap but no finished app -> `Planned`.
- Recent idea with no canonical implementation yet -> `Concept`.
- Superseded/reference-only project -> `Legacy`.

No exact delivery dates were invented. The `eta` field is a stage label unless a source provides a real schedule.
