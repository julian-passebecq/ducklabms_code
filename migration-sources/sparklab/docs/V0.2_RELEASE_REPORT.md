# V0.2 release report

## Added

- Four selectable case studies: NYC Taxi, Contoso Retail CDC, Open Lakehouse,
  Energy Telemetry.
- Global architecture overview separating source/file formats, table formats,
  compute, transformation, orchestration and consumer layers.
- Interop workspace with DuckDB / Polars / DuckLake responsibility matrix.
- Avro CDC, Iceberg, Polars/Arrow, Delta and Lance lab directions.
- DuckLake feature map: transactions, time travel, schema evolution,
  partitioning, change feed and maintenance.
- MotherDuck Flights comparison alongside Airflow.
- New integration scaffolds under `services/cases/` and `services/motherduck/`.

## Truth boundary

All UI state remains deterministic and is labelled **SIMULATED STATE**.
V0.2 does not claim live execution against MotherDuck, an Iceberg REST catalog,
or a local DuckLake runtime.

## Checks

- `node --check prototype/app.js`: PASS.
- Python case scaffolds: syntax checked with `py_compile`.
- TypeScript parse reached only missing dependency/type errors because npm
  registry access timed out; no additional TypeScript syntax diagnostics were
  emitted before those missing-module errors.
- Chromium visual QA could not complete in this container because the headless
  Chromium process hangs on unavailable system DBus. The standalone file is
  included for local browser QA.
