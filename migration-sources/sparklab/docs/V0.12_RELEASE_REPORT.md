# V0.12 Release Report — runtime truth + live SQL

## Scope

V0.12 deliberately avoided another shell redesign. The pass targeted runtime truth, compiler fidelity, cost accounting and a useful second live notebook runtime.

## Major fixes and improvements

### 1. SQL runtime is live

The `SQL (DuckDB)` selector now calls `POST /sql/run` when the FastAPI backend is connected. The endpoint executes one bounded read-only SQL query against the selected case fixture.

- DuckDB is preferred when the optional package exists.
- SQLite is the explicit fallback.
- The response contains engine/scope/rows/schema/timing and deterministic hashes.
- No Spark stages, Spark cost or fake Spark runtime are attached to SQL-only execution.

In the release environment, DuckDB could not be installed because outbound package access was unavailable, so the release correctly reports SQLite as the active bounded oracle. No DuckDB execution is claimed.

### 2. `select("*")` compiler bug fixed

The prior compiler could emit a quoted SQL string for wildcard selection. V0.12 emits a real wildcard and preserves the known source schema.

### 3. More common PySpark expressions

Added safe support for:

- `withColumnRenamed`;
- multi-key joins;
- `F.when(...).otherwise(...)` and chained conditions;
- `cast`;
- `isin`;
- `between`.

These are parsed into the internal expression/relational representation; arbitrary Python execution remains forbidden.

### 4. Cost model now includes the driver

Virtual job accounting now distinguishes worker allocation, task work and driver allocation. `core_hours`, memory GB-hours and node-hours include the driver/cold-start portion. Slot utilization exposes the difference between allocated worker time and useful task work.

### 5. Static fallback/runtime drift guard

The static React fallback is generated from the current SparkLab runtime/truth packs. A regression test requires the checked-in preview JSON to equal a newly generated preview.

### 6. Finance UI statistics aligned with the calibrated truth pack

Finance now consistently uses 61.84M rows and calibrated shuffle-partition evidence instead of mixing source-file and shuffle-partition statistics.

### 7. Result banner truth fix

An arbitrary SQL query may execute successfully without being comparable to a mission truth pack. `verified = null` now renders as neutral “bounded semantic execution complete” rather than being falsely shown as a mismatch.

## Truth boundary after V0.12

### Real

- safe parsing and relational compilation;
- bounded SQL/PySpark semantic result execution;
- actual bounded rows/schema/provenance;
- truth-pack data statistics;
- explicit backend capability detection.

### Modeled

- Spark workers/executors;
- stages/tasks;
- shuffle/skew/AQE;
- spill/memory pressure;
- virtual duration;
- normalized/fabric-like/databricks-like usage.

### Still not claimed

- real distributed Spark;
- full-scale case-data execution;
- real Fabric/Databricks scheduler internals;
- vendor billing.
