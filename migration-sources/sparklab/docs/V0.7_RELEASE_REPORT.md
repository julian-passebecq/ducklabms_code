# V0.7 Release Report - Connected Notebook Loop

## Objective

Make the V0.6 Fabric-inspired workbench behave more like an actual training notebook without weakening the project's truth boundary.

## Implemented

### Connected PySpark notebook path

- Added `src/api.ts`.
- Added backend health check.
- Added `POST /notebook/run`.
- PySpark notebook submissions are parsed through the safe AST evaluator.
- Retail submissions return the compiled plan, virtual Spark job, cost adapters and truth-pack grade.
- Uncalibrated cases return the compiled semantic plan without inventing distributed-runtime results.

### Notebook output

- Result tab.
- Plan tab.
- Grade tab.
- Running / success / error cell state.
- Execution counter and control-plane duration.
- Compile/runtime errors render inside the notebook instead of silently falling back.

### Diagnostics

- Spark UI can consume live backend stage data.
- Added Compare inspector for Retail baseline vs optimized physical behavior.
- Cost inspector uses live run values when available.
- Quality inspector exposes the truth-pack grade.
- Lakehouse inspector now follows the table selected in Explorer and shows its schema.

### Learning progression

- Successful mission execution marks that mission completed for the active case.
- Resources and Missions surfaces show completion state.

### Standalone behavior

The standalone artifact remains dependency-free. It does not fake a live backend connection: it displays `Standalone fallback`, uses the reference truth pack, and provides Result / Plan / Grade-style educational surfaces.

## Truth boundary

### Real / directly validated

- user-submitted PySpark subset parsing
- compiled relational plan
- case schemas and known statistics
- API validation and exercise truth-pack checks

### Dataset-grounded simulation

- Spark stages/tasks
- workers/slots
- shuffle and spill estimates
- AQE decisions
- modeled runtime
- vendor-equivalent usage

### Not claimed

- exact Fabric runtime
- exact Databricks runtime
- JVM GC behavior
- real executor network traffic
- exact cloud wall-clock
- vendor invoice

## Validation

- Python/API/static UI: 21 tests passed.
- Standalone inline JavaScript: `node --check` passed.
- React/TypeScript source: strict TypeScript check passed using temporary React declaration stubs in the offline build environment.
