# V0.9 Release Report — Semantic Truth and Runtime Consistency

## Scope

V0.9 keeps the V0.8 Fabric-inspired shell and SparkLab scheduler. The pass focuses on whether a learner can trust the relationship between submitted code, returned values, physical-plan evidence and verified downstream state.

## Defects found and fixed

### Semantic correctness was plan-only

V0.8 could prove that a plan contained `groupBy(customer_id)`, `SUM(net_amount)` and `COUNT(*)`, but that did not prove the returned values were correct. V0.9 adds deterministic bounded query execution for calibrated Retail missions and uses returned rows/schema as the semantic oracle.

### Compile and calibrated runtime could disagree on broadcast

The generic training estimator knew the 6.4 MB dimension size and could report an automatic broadcast candidate. Retail Mission 03 intentionally withholds catalog size statistics, so its calibrated baseline correctly used SortMergeJoin. V0.9 adds catalog-statistics availability to case profiles and makes the compiler/training plan honor it.

### New semantic tests were not in the root test path

The semantic executor initially had direct tests but `pytest.ini` did not include `services/semantic`. The default project-level release gate now includes those tests.

### Main Lakehouse/Consumer pages used request success instead of verified grade

The Inspector required a passing grade, but the main pages could advance after any calibrated backend run. V0.9 gates all verification state on a passing truth-pack grade.

## Bounded fixture

Retail fixture data intentionally includes:

- positive orders
- zero and negative amounts that must be filtered
- multiple customer groups
- the known `CORPORATE_ACCOUNT_01` key
- a small segment dimension

Expected bounded result:

```text
customer_id            revenue   orders
C001                     150.0        2
C002                     225.0        2
C005                     100.0        2
C006                      10.0        1
CORPORATE_ACCOUNT_01    4500.0        3
```

This is a correctness oracle only. It does not substitute for the 184,229,821-row case-study scale used by the Spark simulator.
