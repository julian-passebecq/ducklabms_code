# V0.11 Release Report — Finance Windows + Semantic Hardening

## Baseline

V0.10 passed its clean release gate before changes began.

## Defects / gaps found

1. Only Retail had a fully calibrated distributed + semantic learning loop even though Finance already exposed ordered-window content in the UI.
2. Common notebook imports such as `from pyspark.sql.functions import col` were syntactically accepted but the imported symbol was not bound.
3. Common PySpark boolean syntax using `&`, `|`, `~`, and `df["column"]` was unsupported.
4. Explicit PySpark window constants (`Window.unboundedPreceding`, `Window.currentRow`) were unsupported.
5. Bounded semantic provenance hashed only the visible preview, so a truncated preview could not prove a complete bounded result even when the fixture itself was small enough to execute fully.
6. The semantic query guard did not explicitly reject internal semicolons / multiple statements before backend execution.
7. UI partition labeling was ambiguous between source partitions, shuffle partitions, and post-AQE tasks.
8. Finance Explorer schema omitted `balance` and `loaded_at`, which were present in the actual profile/fixture.

## Implemented

### Finance calibrated truth pack

Added `finance_account_window_03` with:

- 61.84M modeled transactions
- 9.7 GB modeled input
- 365 source files
- 200 post-exchange partitions
- 41 MB modeled median post-shuffle partition
- 278 MB hot account partition
- real bounded fixture truth for `lag(amount)` + running sum

The virtual runtime models:

```text
Parquet scan
    -> Exchange(account_id)
    -> Sort(transaction_ts)
    -> Window
```

A global ordered window intentionally collapses to one virtual task and can spill. For a correct `account_id` window, the hot account stays co-located: the simulator does **not** reuse Retail's skew-join split behavior because that would change ordered-window semantics.

### Parser fidelity

Added safe support for:

- imported function aliases
- `df["column"]`
- `&` / `|` Spark expression composition
- unary `~`
- `Window.unboundedPreceding`
- `Window.currentRow`
- `Window.unboundedFollowing`

### Semantic provenance

Added:

- `result_sha256`
- `verification_complete`
- full bounded-result canonical hashing independent of row/column order
- a 10,000-row bounded verification ceiling

Preview truncation no longer automatically blocks verification when the complete bounded result was safely computed internally.

### SQL safety

Bounded semantic execution now rejects multiple SQL statements before reaching the backend.

### UI

- Finance mission 03 routes to the calibrated truth pack.
- Finance mission starter code uses an explicit `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` frame.
- Result view shows query / full-result / preview fingerprints.
- Spark summary shows task-shape transition (`scan -> final`) rather than one ambiguous partition count.
- Finance-specific ordered-window diagnosis added to the inspector.

## Remaining intentional limitation

DuckDB Python is capability-detected but is not installed in this execution environment, so the packaged release validates SQLite as the dependency-free bounded correctness oracle. Full case-study DuckDB/DuckLake execution remains a separate next adapter; the product does not claim those large datasets were executed here.
