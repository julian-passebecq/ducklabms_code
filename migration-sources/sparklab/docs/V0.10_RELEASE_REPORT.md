# V0.10 Release Report — Semantic Provenance and Compiler Fidelity

## Scope

V0.10 keeps the V0.9 Fabric-inspired notebook and virtual Spark scheduler. This pass improves the trust boundary between PySpark source, relational semantics, bounded result execution, and virtual distributed behavior.

## Changes

### 1. Pluggable bounded semantic engine

`semantic_engine` now accepts `auto`, `duckdb`, or `sqlite`.

- `auto` prefers DuckDB when the optional Python package is present.
- SQLite remains the dependency-free fallback.
- `/capabilities` reports availability and the selected automatic engine.
- requesting unavailable DuckDB returns explicit unsupported semantic evidence rather than fabricating a DuckDB run.

The current build environment has no DuckDB Python wheel installed, so release tests validate the SQLite fallback and capability behavior. `services/api/requirements-duckdb.txt` provides the optional dependency for normal environments.

### 2. Execution provenance

Bounded results now include:

- engine key and label
- dataset scope
- row count, schema and preview rows
- query SHA-256
- preview SHA-256
- preview truncation state
- semantic elapsed milliseconds

The React and standalone Result views display shortened fingerprints.

### 3. Safer verification

A truncated preview cannot be compared as if it were the complete truth-pack result. Verification is withheld (`verified = null`) instead.

### 4. PySpark compiler fidelity

- `dropDuplicates()` without arguments now works as whole-row distinct.
- `withColumn("existing", ...)` replaces a known existing column and preserves its position rather than duplicating the name.
- `drop()` emits portable explicit projections when source schema is known.
- keyed joins with known schemas expose the join key once and append only non-key right-side columns.
- source-column metadata was added to case profiles.
- dedupe projections avoid DuckDB-only `EXCLUDE` syntax when schema is known.

These changes make more compiled transformations executable by both the bounded SQLite oracle and the preferred DuckDB path.

## Truth boundary

### Real

- safe PySpark-subset AST parsing
- deterministic relational SQL compilation
- bounded fixture SQL execution
- real returned schema and rows
- execution fingerprints
- known case statistics

### Dataset-grounded simulation

- Spark workers/executors
- stages/tasks
- shuffle and skew
- AQE split behavior
- memory/spill model
- virtual duration
- vendor-equivalent usage

### Not claimed

- execution of the 184M-row Retail dataset in the packaged demo
- a real Spark JVM cluster
- exact Fabric/Databricks scheduling
- vendor billing
